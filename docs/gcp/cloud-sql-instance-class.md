# Cloud SQL for MySQL のエディション別マシン系列まとめ

GCP の Cloud SQL for MySQL では、エディションによって選べるインスタンスの系列が異なります。

大きく分けると、以下のように理解するとわかりやすいです。

```txt
安さ重視
  ↓
Enterprise: 汎用共有コア
  ↓
Enterprise: 汎用専用コア
  ↓
Enterprise: N4
  ↓
Enterprise Plus: N2 / C4A
  ↓
高性能・高可用性重視
```

---

## 1. エディションごとに選べるマシン系列

| エディション | 選べる主なマシン系列 |
|---|---|
| Enterprise | 汎用共有コア |
| Enterprise | 汎用専用コア |
| Enterprise | N4 |
| Enterprise Plus | N2 |
| Enterprise Plus | C4A |

つまり、最安の `db-f1-micro` を使いたい場合は **Enterprise** を選ぶ必要があります。

**Enterprise Plus では `db-f1-micro` は選べません。**

---

## 2. 全体比較

| エディション | マシン系列 | 特徴 | 最小構成の目安 | ストレージ | 向いている用途 |
|---|---|---|---:|---|---|
| Enterprise | 汎用共有コア | 最安。CPU共有。SLA対象外 | db-f1-micro / db-g1-small | SSD または HDD | 個人開発、検証、低負荷 |
| Enterprise | 汎用専用コア | vCPU/メモリを柔軟に指定 | 1 vCPU + 3.75GB以上 | SSD または HDD | 小〜中規模本番 |
| Enterprise | N4 | 新しめの汎用系列。バランス型 | 2 vCPU以上 | Hyperdisk Balanced | 新規本番、安定性能 |
| Enterprise Plus | N2 | 高性能・高可用性。1 vCPU: 8GB固定 | 2 vCPU + 16GB | SSD | 重要な本番DB |
| Enterprise Plus | C4A | 高需要ワークロード向け。高い価格性能 | 2 vCPU + 16GB | Hyperdisk Balanced | 高負荷、性能重視 |

---

# 用語解説

表を読む前に、つまずきやすい用語を整理します。

## vCPU とは

vCPU = virtual CPU（仮想CPU）。インスタンスに割り当てられる CPU の単位で、GCP では通常
**物理コアの1スレッド（ハイパースレッド）= 1 vCPU** です（AWS の vCPU と同じ概念）。

- **共有コア**（`db-f1-micro` / `db-g1-small`）: 1コアを丸ごともらえず、**他インスタンスと共有した一部の CPU 時間**だけ使う。
  だから表では `vCPU = shared` と書かれ、最安だが性能が不安定。
- **専用コア**: vCPU 数ぶんを**自分専用に確保**する。vCPU が多いほど並列処理性能が上がる。

## 専用コアのメモリ制約（最小 3.75 GiB）

Enterprise の汎用専用コア（`db-custom-{vCPU}-{メモリMB}`）では、**vCPU 数と合計メモリを別々に指定**します。
メモリは「1 vCPU ごとの値」を入力するのではなく、**合計メモリ（MB）を個別に指定**します。
ただしその合計値は、選んだ vCPU 数に応じて決まる次の範囲を満たす必要があります。

- 下限: **0.9 GB × vCPU 数**（かつ**合計の絶対下限 3.75 GB**）
- 上限: **6.5 GB × vCPU 数**
- **256 MB の倍数**であること

つまり「vCPU を決める → その vCPU 数に応じてメモリの**選べる範囲**が決まる → その範囲内で合計メモリを自由に選ぶ」流れです
（コンソールでも vCPU を選ぶとメモリスライダーの可動域が変わる）。例: `db-custom-2-7680` = 2 vCPU / 合計 7,680 MB。

そのため 1 vCPU の場合、「0.9 GB/vCPU」の理屈上は 0.9 GB でも、**絶対下限 3.75 GB が効いて 3.75 GiB 未満にはできません**。
これが「専用コアの最小構成 = 1 vCPU + 3.75 GiB」の理由です（もっと積むことはできるが、減らせない）。

## Hyperdisk Balanced とは（SSD との違い）

N4 / C4A などの新しめの系列が採用するストレージ。従来の「SSD」とはフラッシュベースである点は同じですが、
**性能の決まり方が違います**。

| | SSD（PD-SSD / 永続ディスク） | Hyperdisk Balanced |
|---|---|---|
| 世代 | 従来型 | 新世代 |
| 性能（IOPS/スループット） | **容量に連動**（大きくしないと速くならない） | **容量とは独立に指定**できる |
| 課金 | 容量ベース | 容量 + ベースライン超の IOPS/スループットは別課金 |

要するに **Hyperdisk Balanced = 容量と性能を切り離して個別に調整できる次世代 SSD**、
**SSD(PD-SSD) = 性能が容量に紐づく従来型**、という理解で OK です。

> 今回の構成（`db-f1-micro` = 共有コア）は SSD/HDD を使うため、Hyperdisk Balanced は関係しません。
> Hyperdisk Balanced は N4 / C4A を選んだときに出てくる選択肢です。

# Enterprise のマシン系列

## 3. Enterprise: 汎用共有コア

汎用共有コアは、Cloud SQL for MySQL で一番安く使える系列です。

代表的なマシンタイプは以下です。

| マシンタイプ | vCPU | メモリ | 特徴 |
|---|---:|---:|---|
| db-f1-micro | shared | 0.6 GiB | 最安 |
| db-g1-small | shared | 1.7 GiB | f1-microより少し余裕あり |

料金目安は以下です。

| 構成 | インスタンス月額目安 |
|---|---:|
| db-f1-micro | 約 $7.67 / 約1,240円 |
| db-g1-small | 約 $25.55 / 約4,120円 |

前提:

```txt
1か月 = 730時間
1ドル = 約161.3円
ストレージ・バックアップ・ネットワーク・HAは別
```

### 特徴

```txt
メリット:
- とにかく安い
- 個人開発や検証環境に向いている
- Cloud SQLを低コストで試せる

デメリット:
- CPUが共有
- メモリが少ない
- Cloud SQL SLA対象外
- 本番の重要DBには向きにくい
```

### 向いている用途

```txt
- 個人開発
- 検証環境
- 学習用途
- 低負荷な管理画面
- 一時的な開発DB
```

---

## 4. Enterprise: 汎用専用コア

汎用専用コアは、従来の Cloud SQL でよく使われる標準的な専用コア構成です。

`db-custom-{CPU}-{Memory}` のように、CPU とメモリをある程度自由に指定できます。

例:

```txt
db-custom-1-3840
db-custom-2-7680
db-custom-4-15360
```

### 最小構成の例

```txt
1 vCPU + 3.75 GiB
```

料金目安:

```txt
vCPU: $0.0413 / 時間
メモリ: $0.007 / GiB時間

1 vCPU + 3.75 GiB
= $0.0413 + $0.007 × 3.75
= $0.06755 / 時間

$0.06755 × 730時間
= 約 $49.31 / 月
= 約7,950円 / 月
```

### 特徴

```txt
メリット:
- CPUが共有ではない
- 共有コアより本番向き
- vCPUとメモリを比較的柔軟に選べる
- N4やEnterprise Plusより安く抑えやすい

デメリット:
- db-f1-microよりはかなり高い
- 高性能・高可用性機能はEnterprise Plusより弱い
```

### 向いている用途

```txt
- 小規模本番DB
- 中規模Webアプリ
- コストを抑えたい本番環境
- db-f1-microでは不安な環境
```

---

## 5. Enterprise: N4

N4 は Enterprise で選べる新しめの汎用マシン系列です。

汎用専用コアよりも新しい世代の選択肢で、バランスのよい価格性能を狙う場合に候補になります。

### 最小構成の例

```txt
2 vCPU + 4 GiB
```

料金目安:

```txt
vCPU: $0.0413 / 時間
メモリ: $0.007 / GiB時間

2 vCPU + 4 GiB
= $0.0413 × 2 + $0.007 × 4
= $0.1106 / 時間

$0.1106 × 730時間
= 約 $80.74 / 月
= 約13,000円 / 月
```

### 特徴

```txt
メリット:
- 新しめの汎用系列
- 本番向けに使いやすい
- Hyperdisk Balanced を利用
- 性能とコストのバランスがよい

デメリット:
- 最小でも2 vCPUから
- 個人開発や検証用途にはやや高い
- 汎用専用コアの最小構成より高くなりやすい
```

### 向いている用途

```txt
- 新規本番環境
- ある程度アクセスがあるWebアプリ
- 汎用専用コアより新しい構成を使いたい場合
- 性能とコストのバランスを取りたい場合
```

# Enterprise Plus のマシン系列

## 6. Enterprise Plus: N2

N2 は Enterprise Plus 側の標準的な高性能系列です。

Enterprise Plus は、Enterprise よりも可用性・性能・運用機能が強化されています。

### 最小構成

```txt
2 vCPU + 16 GiB
```

料金目安:

```txt
vCPU: $0.0537 / 時間
メモリ: $0.0091 / GiB時間

2 vCPU + 16 GiB
= $0.0537 × 2 + $0.0091 × 16
= $0.253 / 時間

$0.253 × 730時間
= 約 $184.69 / 月
= 約29,800円 / 月
```

### 特徴

```txt
メリット:
- Enterpriseより高可用性
- Enterpriseより高性能
- SLAが高い
- メンテナンス時の停止時間を抑えやすい
- 重要な本番DB向き

デメリット:
- 最小構成でも高い
- 個人開発・小規模サービスでは過剰になりやすい
```

### 向いている用途

```txt
- 重要な本番DB
- DB停止の影響が大きいサービス
- 高可用性を重視するサービス
- 金融、医療、大規模SaaSなど
```

---

## 7. Enterprise Plus: C4A

C4A は Enterprise Plus で選べる、高性能・高価格性能寄りの系列です。

N2 と同じく Enterprise Plus の機能を利用できますが、ストレージには Hyperdisk Balanced を使います。

### 最小構成

```txt
2 vCPU + 16 GiB
```

料金目安:

```txt
vCPU: $0.054 / 時間
メモリ: $0.009 / GiB時間

2 vCPU + 16 GiB
= $0.054 × 2 + $0.009 × 16
= $0.252 / 時間

$0.252 × 730時間
= 約 $183.96 / 月
= 約29,700円 / 月
```

### 特徴

```txt
メリット:
- 高性能ワークロード向け
- Hyperdisk Balanced を利用
- N2と近い価格帯
- Enterprise Plusの高可用性・高性能機能を使える

デメリット:
- 最小構成でも高い
- MySQLバージョン要件がある
- 作成後のマシン系列変更などに制約がある
- レプリカや復元先も同じ系列が必要になる場合がある
```

### 向いている用途

```txt
- 高負荷な本番DB
- 性能重視のDB
- 新しい高性能系列を使いたい場合
- Hyperdisk Balancedを使いたい場合
```

# 8. 料金差のざっくり比較

インスタンス料金だけで比較すると、だいたい以下のようなイメージです。

| 系列 | 代表構成 | 月額目安 |
|---|---|---:|
| Enterprise 汎用共有コア | db-f1-micro | 約1,240円 |
| Enterprise 汎用共有コア | db-g1-small | 約4,120円 |
| Enterprise 汎用専用コア | 1 vCPU / 3.75GB | 約7,950円 |
| Enterprise N4 | 2 vCPU / 4GB | 約13,000円 |
| Enterprise Plus N2 | 2 vCPU / 16GB | 約29,800円 |
| Enterprise Plus C4A | 2 vCPU / 16GB | 約29,700円 |

注意点:

```txt
上記はインスタンス料金のみの目安です。

別途かかる可能性があるもの:
- ストレージ料金
- バックアップ料金
- ネットワーク料金
- HA構成の追加料金
- Hyperdisk Balanced のIOPS/スループット追加料金
```

# 9. ストレージ料金の目安

10 GiB 程度だけなら、ストレージ料金自体は大きくありません。

| ストレージ | 10GiB月額目安 |
|---|---:|
| HDD | 約145円 |
| SSD | 約274円 |
| Hyperdisk Balanced 容量 | 約186円 |

ただし、Hyperdisk Balanced は容量だけでなく、ベースラインを超える IOPS やスループットも課金対象になる場合があります。

# 10. Enterprise と Enterprise Plus の主な違い

| 項目 | Enterprise | Enterprise Plus |
|---|---|---|
| 位置づけ | 標準版 | 高性能・高可用性版 |
| 料金 | 安い | 高い |
| 最安構成 | db-f1-micro が使える | db-f1-micro は使えない |
| 主な系列 | 共有コア / 専用コア / N4 | N2 / C4A |
| 可用性 | 標準 | より高い |
| 性能 | 標準 | より高い |
| 用途 | 開発、小〜中規模本番 | 重要本番、大規模、高負荷 |

# 11. 実務での選び方

## 個人開発・検証環境

```txt
Enterprise + db-f1-micro
```

理由:

```txt
- 最も安い
- MySQLを低コストで使える
- 学習・検証・個人開発に向いている
```

注意点:

```txt
- SLA対象外
- メモリが少ない
- 本番の重要DBには不向き
```

---

## 小規模な本番環境

```txt
Enterprise + 汎用専用コア
```

または

```txt
Enterprise + N4
```

理由:

```txt
- 共有コアより安定している
- Enterprise Plusより安い
- 小〜中規模のWebアプリに使いやすい
```

---

## ある程度ちゃんとした本番環境

```txt
Enterprise + N4
```

理由:

```txt
- 新しめの汎用系列
- 性能とコストのバランスがよい
- Hyperdisk Balancedを使える
```

ただし、最小でも2 vCPUからなので、コストは上がりやすいです。

---

## 高可用性・性能重視の本番環境

```txt
Enterprise Plus + N2
```

または

```txt
Enterprise Plus + C4A
```

理由:

```txt
- Enterprise Plusの高可用性機能を使える
- 性能が高い
- DB停止の影響が大きいサービスに向いている
```

注意点:

```txt
- 最小構成でも月3万円前後になりやすい
- 個人開発や小規模サービスでは過剰になりやすい
```

---

# 12. 結論

コスト重視なら、まずは以下です。

```txt
Enterprise + db-f1-micro
```

本番で最低限ちゃんと使いたいなら、以下が候補です。

```txt
Enterprise + 汎用専用コア
```

または

```txt
Enterprise + N4
```

重要システムや高負荷DBなら、以下を検討します。

```txt
Enterprise Plus + N2
Enterprise Plus + C4A
```

まとめると、選び方は以下です。

```txt
個人開発・検証
→ Enterprise + 汎用共有コア

小規模本番
→ Enterprise + 汎用専用コア

新規本番・バランス重視
→ Enterprise + N4

重要本番・高可用性・高性能
→ Enterprise Plus + N2 / C4A
```

特にコストを抑えたい場合は、**Enterprise Plus を選ばないこと**が重要です。

`db-f1-micro` や `db-g1-small` を使いたい場合は、**Enterprise の汎用共有コア** を選びます。
