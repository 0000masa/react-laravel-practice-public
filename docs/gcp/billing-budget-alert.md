# 予算アラート（コスト通知メール）の設定手順

AWS で作っていた **「想定外の課金が出たらメールで気づく」**（いわゆる Zero-Spend Budget）の
GCP 版。Cloud Billing の**予算アラート**をコンソールで作成する。

- 方式: **GCP ネイティブの予算アラート**（コンソールのみ・gcloud CLI 不使用）。
- スコープ: **請求アカウント全体**（AWS の「アカウント単位の Zero-Spend」に対応）。
- 通貨: 例示は **JPY**。請求アカウントの通貨に読み替える。
- これは請求アカウント単位のリソースで、project-scoped な `terraform/gcp/` とは層が違うため
  **`terraform import` の対象外**（コンソールで作って終わり。`imports.tf` にも書かない）。

---

## ⚠️ 最重要: AWS と GCP で「日次通知」の挙動が違う

AWS で作ったのは **日次予算**（$1 予算・ACTUAL > $0.01）で、AWS 側が**毎日「昨日いくら使ったか」を
メール送信**してくれる仕組みだった。**GCP の予算アラートでは同じことはできない。**

| | AWS Budgets（日次予算） | GCP Cloud Billing 予算 |
| --- | --- | --- |
| 集計期間 | **日次**（毎日リセット） | **月次が基本**（カレンダー月初でリセット）。日次期間は選べない |
| 通知タイミング | 毎日（その日の金額を1通） | しきい値を**超えた瞬間に1回だけ**。毎日は再送されない |
| しきい値 | 金額（> $0.01 など） | **予算額に対する累計支出の％**（例 1% / 50% / 100%） |

つまり GCP では:

> しきい値を一番小さくしても「**ほぼ毎日**」にはならない。
> 「その月の累計支出が初めてその％を超えた日に1通 → あとは次のしきい値か翌月まで沈黙」になる。

**「毎日その日の金額をメール」を完全再現するには**、`予算 → Pub/Sub → Cloud Functions`（または
`Cloud Scheduler + BigQuery 課金エクスポート`）で**通知用のコードを書いてデプロイ**する必要がある
（→ [発展](#発展毎日メールしたい場合)）。本プロジェクトの「コンソールのみ・最小構成」方針からは外れる
ため、ここでは採用しない。

ただし AWS 設定の**本来の目的**＝「意図しない課金が発生したら即気づく」は、
GCP ネイティブの予算アラートで**十分に達成できる**。「毎日メールという形」は諦め、「お金が動いたら
気づく」という目的を再現する、というのがこのドキュメントの方針。

---

## 0. 前提

- 請求アカウントに対して **請求先アカウント管理者** か、予算を編集できるロールを持っていること。
- 通知は**役割ベース（デフォルト）**で送る。つまり請求アカウントの
  **「請求先アカウント管理者」「請求先アカウント ユーザー」ロールを持つ全員のメール**に届く。
  ソロ運用ならログインに使っている自分のアドレスに届く。任意の別アドレスに送りたい場合は
  Cloud Monitoring の通知チャネルが必要（本手順では使わない）。

## 1. 予算の作成

コンソール: **お支払い（Billing）→ 予算とアラート（Budgets & alerts）→ 予算を作成**。

### 1-1. スコープ

- 期間: **月別（Monthly）**（GCP に日次期間は無い）
- 範囲: **請求アカウント全体**（プロジェクト・サービス・ラベルでの絞り込みはしない）
- **コスト削減（クレジット）**: 表示されるクレジットを**すべてチェックして差し引く**。
  これで予算は「**実際に財布から払う純額**」を追跡する（AWS の「ACTUAL > $0.01」に忠実）。

> **コスト削減（クレジット）とは**: 予算が追跡する金額を「合計費用 −（選択したクレジット）」にする設定。
> チェックして選んだクレジットだけが差し引かれる。
>
> | | 挙動 | 向き |
> | --- | --- | --- |
> | **全部チェック（純額・採用）** | 無料枠やトライアル（$300）でカバーされている間は ¥0 扱い → **アラートは鳴らない**。本当にお金が出始めた瞬間だけ通知 | AWS Zero-Spend と同じ感覚・ノイズが少ない |
> | チェックしない（総額） | 無料枠/トライアルでタダでも「使った分」が費用として見え、使い始めた時点で通知 | トライアル消費の監視向け・ノイズは増える |
>
> 主要なのは **無料枠のクレジット**（Always Free 枠）と **プロモーション クレジット**（$300 トライアル等）。
> 残り（継続利用割引 SUD / CUD クレジット / 費用ベースの割引 / サブスクリプション 等）も
> まとめてチェックして差し引いておけば、純額ベースで揃う。

### 1-2. 金額

- 予算タイプ: **指定額（Specified amount）**
- 目標額: **¥0（ゼロ）**

> しきい値は「予算額 × ％」で金額に換算される。予算額が 0 なら **どのしきい値も ¥0 に潰れる**ので、
> 支出が ¥0 を少しでも超えた時点で発火する＝**「最初の1円」で鳴る純粋な Zero-Spend** になる。
> A（クレジットを差し引く＝純額）と組み合わさり、「無料枠・トライアルでカバーされている間は鳴らず、
> 実際に財布から出た瞬間に鳴る」挙動になる。

### 1-3. しきい値ルール（アクションの設定）

しきい値は **実際の支出額（Actual）** で設定する（**予測値（Forecasted）は使わない**＝
AWS の ACTUAL に合わせる）。

| しきい値（％） | 予算 ¥0 での金額 | 意味 |
| --- | --- | --- |
| **100%** | ¥0 | **その月で最初に課金（純額 > ¥0）が発生したら1通**（AWS の > $0.01 相当） |

> 予算 ¥0 では全しきい値が ¥0 に潰れるため、**しきい値は1本でよい**（複数足しても全部同じ ¥0 で意味がない）。
> 「課金あり / なし」の1段階の通知になる。段階的な警告（50% / 90%…）が欲しい場合のみ、予算額を
> 小額（例 ¥150）にして複数しきい値を置く構成に戻す。

### 1-4. 通知先（通知の管理）

「通知の管理」には4つのチェック項目がある。今回は**1つ目だけにチェック**する。

| 項目 | 送信先 / 役割 | 今回 |
| --- | --- | --- |
| **メール通知アラートを課金管理者とユーザーに送信する** | 請求先アカウントの**管理者（`roles/billing.admin`）とユーザー（`roles/billing.user`）**全員。ソロ運用なら自分のログインアドレス | **チェック**（役割ベース） |
| **メール通知アラートをプロジェクト オーナーに送信する** | 予算対象プロジェクトの**オーナー（`roles/owner`）**全員 | チェック不要（後述の理由で**グレーアウト**） |
| **モニタリング メール通知チャネルをこの予算にリンクする** | Cloud Monitoring の通知チャネルで指定した**任意のメールアドレス**（役割と無関係に送れる）。Monitoring 側でチャネル作成が必要 | オフ（コンソールのみ・最小構成） |
| **Pub/Sub トピックをこの予算に接続する** | メールではなく **Pub/Sub トピック**へ支出データをプログラム送信（Cloud Functions 等で加工・転送する用） | オフ |

> **「プロジェクト オーナーに送信する」がグレーアウトする理由は、予算スコープを「請求アカウント全体」に
> したから。** このオプションは**予算スコープを単一プロジェクトに絞ったときだけ有効**で、請求アカウント
> 全体や複数プロジェクトでは「どのプロジェクトのオーナーに送るか」が定まらないため無効化される。
> **単一 Google アカウントか / Workspace で複数ユーザーか、は無関係**（よくある誤解）。
> 単一プロジェクトだけを監視する構成にすればチェック可能になる。
>
> 今回の通知は1つ目（課金管理者とユーザー）だけで届くので、グレーアウトは無視してよい。

> **`roles/billing.admin` とは（IAM ロールと AWS 対比）**
> `roles/billing.admin` は GCP の**事前定義 IAM ロール**（表示名「請求先アカウント管理者」）で、
> `billing.accounts.update` 等の**権限を束ねたもの**。**請求アカウントというリソースに対して**付与される。
> 通知先は「その請求アカウント上で `roles/billing.admin` または `roles/billing.user` を付与された
> プリンシパル全員」。ただし実際にメールが届くのは受信箱を持つ相手（人間のユーザー・グループ
> アドレス）で、ロールを持っていてもサービスアカウントには届かない。ソロ運用なら該当＝自分1人。
>
> AWS との対応（用語が紛らわしいので注意）:
>
> | GCP | 中身 | AWS の近い概念 |
> | --- | --- | --- |
> | ロール（role） | 権限の**束** | **管理ポリシー（managed policy）** |
> | IAM ポリシー（allow policy） | 「誰に・どのロールを・どのリソースで」与える**結びつけ** | ポリシーの**付与/アタッチ関係**（ポリシー文書ではない） |
> | プリンシパル / メンバー | user / group / サービスアカウント等 | IAM ユーザー / グループ等 |
>
> - 「GCP ロール ≈ AWS 管理ポリシー（権限の束）」で捉えるのが正解。
> - ⚠️ **GCP の「ロール」≠ AWS の「ロール」**。AWS の IAM ロール（assume するアイデンティティ）は
>   GCP では**サービスアカウント**が近い。名前が同じでも別物。
> - GCP の「IAM ポリシー」は権限の束ではなく**バインディング**を指す点も AWS と意味が違う。

**保存**して完了。

## 動作の確認イメージ

- 何も課金がなければメールは来ない（Zero-Spend の状態）。無料枠・トライアルでカバーされている間も
  純額 ¥0 なので鳴らない。
- 月の途中で純額（実際に払う額）が ¥0 を超えた時点でメールが1通届く。
  → 「想定外の課金が始まった」サインとして扱う。
- 翌月になると累計がリセットされ、また最初の課金でメールが届く。

> **毎日は来ない**点を忘れない。届かない＝「その月はまだ ¥1.5 を超えていない」だけで、
> 「監視が効いていない」わけではない。

## AWS との対応（まとめ）

| AWS | GCP |
| --- | --- |
| AWS Budgets（My Zero-Spend Budget） | Cloud Billing 予算（請求アカウント全体スコープ） |
| 日次予算・毎日メール | 月次・しきい値超過時に1回（日次相当は無い） |
| 予算 $1 / ACTUAL > $0.01 | 予算 ¥0 / Actual 100%（純額 > ¥0 で発火） |
| 通知先 = SNS / メール | 役割ベース（請求先アカウント管理者・ユーザー） |
| ― | `terraform import` 対象外（請求アカウント層・コンソールのみ） |

## 発展（毎日メールしたい場合）

「毎日その日の金額を1通」を本当に再現したいなら、コンソールだけでは閉じず以下が必要になる
（このプロジェクトでは採用しないが、選択肢として記録）。

- **予算 → Pub/Sub → Cloud Functions**: 予算の通知を Pub/Sub トピックに出し、
  トリガーされた Cloud Functions が金額を整形してメール送信（SendGrid 等）する。
  ただし予算通知の発火は「しきい値超過時」なので、これ単体でも厳密な「毎日」にはならない。
- **Cloud Scheduler + BigQuery 課金エクスポート**: 課金データを BigQuery にエクスポートし、
  毎日 0 時に Cloud Scheduler が起動する Cloud Functions が「昨日の合計」をクエリしてメール送信。
  こちらが AWS の日次メールに挙動として一番近いが、**課金エクスポート設定・BigQuery・関数の
  デプロイ**が必要で、コストも手間も増える。

いずれも通知用コードのデプロイが前提になるため、最小構成では予算アラート（本手順）で代替する。
